## 1. Why this sub-project

SP1/SP1.5/SP1.6 give accounts, workspaces, members and a hardened shell; SP2 puts students into workspaces and stores `Invitation.courseIds` / `InviteLink.courseIds` with nothing to point at. SP3 is the first content sub-project: a teacher builds a course (modules, lessons VIDEO / PDF / TEXT), uploads media that survives a dropped connection, publishes, assigns students; a student sees only what he is enrolled in and what the locking rules allow, and watches or reads behind short-lived signed access with a visible watermark (D-O8). SP4 (progress), SP5 (sessions linked to a course), SP7 (notification centre) and SP10 (activation KPI) build on these tables.

## 4. Flows

### 4.1 Course lifecycle (§10.7)

`POST /workspaces/{wid}/courses` (`course.create`; `sequentialLessons` and lesson `allowDownload` default from `Workspace.settings.default_sequential_lessons` / `default_pdf_download`) → `DRAFT`, owner = caller (ADMIN with `can_teach` or TEACHER / personal OWNER). `PATCH …/courses/{cid}` with `If-Match: "<version>"` (D8); every successful PATCH, module/lesson create/update/delete/reorder bumps `Course.version` (and `Module.version` for lesson changes) — the course version is the editor's single conflict key. Transitions: `publish` (`DRAFT → PUBLISHED`; precondition ≥ 1 non-optional-or-optional module with ≥ 1 lesson whose media is `READY` or whose type is `TEXT` — « leçon READY (média prêt) »; otherwise `422 COURSE_NOT_PUBLISHABLE` with `details.missing: ('NO_MODULE' | 'NO_READY_LESSON')[]` and `details.lessons` still processing), `unpublish` (`PUBLISHED → DRAFT`: enrolled students lose access, enrollments and progress untouched — AC-CRS-02), `archive` (`PUBLISHED → ARCHIVED`), `restore` (`ARCHIVED → PUBLISHED`), `DELETE` (`DRAFT | ARCHIVED` and no `ACTIVE` enrollment → `deletedAt = now`; `PUBLISHED` → `409 COURSE_STATUS_INVALID` with `details.hint = 'ARCHIVE_FIRST'`; ACTIVE enrollments → `409 COURSE_HAS_ACTIVE_ENROLLMENTS` with `details.count` — AC-CRS-05), `reassign` (`course.reassign`, ORGANIZATION only: new owner must be an ACTIVE TEACHER or ADMIN/OWNER with `canTeach`). Every transition is audited (`course.published` … `course.reassigned` with before/after `{ status | ownerUserId }`); `course.published` also enqueues `course.published_notify { courseId }`.

### 4.2 Structure editing (§8.4.2–8.4.3)

Modules and lessons are created at the end (`position = count + 1`). `POST …/courses/{cid}/modules/reorder { moduleIds }` (the full set, no duplicates, else `422`) and `POST …/modules/{mid}/lessons/reorder { lessonIds }` renumber 1..n inside one `withTenantTx` with `SET CONSTRAINTS "module_course_position_key" DEFERRED` (D9) and bump the course version (AC-CRS-04). A lesson's content is set by type at creation and changed by `PATCH …/lessons/{lid}`: `VIDEO` / `PDF` → `mediaAssetId` of an asset of the same workspace, matching `kind`, status `READY` or `PROCESSING` (`PROCESSING` is allowed — §8.4.4 — shown « en cours de traitement », not counted for publication); `TEXT` → `content` validated by `RichTextDocSchema` (§5), inline images must be `READY` `IMAGE` assets of the workspace. `unlockRule.type` other than `NONE` / `PREVIOUS_MODULE_COMPLETED` → `422 VALIDATION_FAILED` (P1). `GET …/courses/{cid}/structure` returns modules → lessons with `media: { id, status, failureReason, durationS, pageCount }` for the editor; `GET …/courses/{cid}` carries `ETag: "<version>"`.

### 4.3 Media upload (§8.4.4, §10.5)

```text
POST /workspaces/{wid}/media/uploads { kind, filename, mimeType, sizeBytes }
  → quota check (D17), limits (D-P15), mime allow-list per kind
  → MediaAsset UPLOADING (uploadUrlExpiresAt = now + 1 h)
  → { mediaId, mode: 'S3_MULTIPART', partSizeBytes: 8 MiB, parts: [{ partNumber, url }] (first 100 presigned, 1 h), expiresAt }
    or { mediaId, mode: 'TUS', uploadUrl, expiresAt }                        (Cloudflare Stream video)
GET  …/media/{mediaId}/upload            → S3_MULTIPART only: parts already stored (ListParts) + fresh URLs for the missing ones (resume, AC-MED-01)
POST …/media/{mediaId}/complete { parts: [{ partNumber, etag }] }   (S3_MULTIPART)
  → CompleteMultipartUpload → HEAD (actual size ≤ limit, else FAILED SIZE_MISMATCH + delete) → signature check on the first 4100 bytes
    (file-type; mismatch → 415 INVALID_FILE_SIGNATURE, object deleted, asset FAILED INVALID_SIGNATURE — AC-MED-04)
  → quota re-check with the actual size (402 → object deleted, FAILED QUOTA_EXCEEDED) → storageUsedBytes += size, countedBytes = size
  → PROCESSING, enqueue media.process { mediaId }
POST …/media/{mediaId}/complete {}       (TUS) → UPLOADING stays until the provider's webhook; the call only records uploadedAt (idempotent)
worker media.process  → PDF: page count (pdf-lib), encrypted → FAILED ENCRYPTED; IMAGE: width/height (image-size); VIDEO (S3): duration/width/height (mp4 probe, §6) → READY (readyAt)
webhook cloudflare    → WebhookEvent (sha256 of the raw body as providerEventId, D11) → media.webhook.process → READY { durationS, width, height, thumbnailUrl, sizeBytes } or FAILED PROVIDER_ERROR
media.cleanup_abandoned (hourly) → UPLOADING > 24 h → FAILED ABANDONED (abort multipart / delete object); PROCESSING > 6 h → Cloudflare: getAsset first (R11); still not ready → FAILED TIMEOUT + email media.failed to the owner (AC-MED-03)
DELETE …/media/{mediaId} → referenced by a lesson of a PUBLISHED course → 409 MEDIA_IN_USE { lessons } (AC-MED-08); by any lesson → 409 MEDIA_IN_USE too (the lesson must drop it first); else DELETING + media.delete job → provider delete → row deleted, storageUsedBytes -= countedBytes
```

Limits (D-P15): VIDEO 4 GiB and 4 h (duration checked at READY: over 4 h → FAILED `SIZE_MISMATCH`), PDF 50 MiB, IMAGE 5 MiB, FILE 10 MiB (message attachments, V2-d — kind accepted, not used by SP3). Mime allow-list: VIDEO `video/mp4`, `video/webm` on the S3 provider (what browsers play natively), plus `video/quicktime`, `video/x-matroska` on Cloudflare (it transcodes); PDF `application/pdf`; IMAGE `image/jpeg`, `image/png`, `image/webp`. The declared `mimeType` is advisory: the signature decides (`file-type`), and `MediaAsset.mimeType` is overwritten with the detected one.

### 4.4 Playback (D-O8, §8.4.4)

- Teacher side: `GET /workspaces/{wid}/media/{mediaId}/playback` (`course.media.manage`, scope `own` = asset owner or owner of a course that references it) and `…/download` (`pdf.download`).
- Student side: `GET /me/lessons/{lid}/playback` and `…/download` after `resolveLessonAccess` (§4.6). `playback` → VIDEO: `{ kind: 'HLS' | 'MP4', url, expiresAt (2 h) }` (Cloudflare: signed JWT in the manifest URL; S3: presigned GET, `Content-Disposition: inline`); PDF: `{ kind: 'PDF', url (5 min, inline), expiresAt, allowDownload }`. `download` → PDF only, `403 DOWNLOAD_NOT_ALLOWED` unless `lesson.allowDownload` (AC-MED-06), presigned 5 min with `attachment; filename=…`. Images in TEXT lessons come as `images: Record<mediaId, url (5 min)>` on the lesson response.
- Issuance is logged (pino `media.playback_issued { mediaId, userId, workspaceId, kind, expiresAt }`) and counted (`media_playback_issued_total`), never audited (D13); a Redis fixed window `playback:{userId}` of 30 per hour → `429 RATE_LIMITED` and a `warn` log line (the alert source). The player re-requests a token silently when the provider answers `403` or the URL is older than `expiresAt − 60 s`; a refused re-request (`403 ENROLLMENT_REVOKED` / `COURSE_NOT_AVAILABLE`) stops the player with « Vous n'avez plus accès à ce cours » (AC-MED-05; the ≤ 10 s progress loop is SP4).

### 4.5 Enrollment (§8.5.1, §10.8)

`POST …/courses/{cid}/enrollments { studentUserIds[] (≤ 200) }` (`enrollment.manage`; scope `own`: the course must be the caller's and every student assigned to him — `TeacherStudentAssignment` — else `422 VALIDATION_FAILED` with the offending ids): each id must be an ACTIVE or consent-pending `STUDENT` membership of the workspace; existing `REVOKED` → back to `ACTIVE` (progress kept, AC-ENR-05); existing `ACTIVE` → unchanged; result lists `{ studentUserId, status, created }`. `ARCHIVED` course → `409 COURSE_STATUS_INVALID` (no new assignment). When the course is `PUBLISHED`, enqueue `course.assigned_notify { enrollmentIds }` (email `course.assigned`, AC-ENR-01); a `DRAFT` course notifies at publication (`course.published_notify`, AC-ENR-02). `DELETE …/enrollments/{uid}` → `REVOKED` (`revokedReason` optional), audit `enrollment.revoked`, `EnrollmentRevokedEvent` (SP5 cancels participations, D-P22). `GET …/enrollments` lists students with `progressPercent`, `completedAt`, `lastActivityAt`; `GET …/courses/{cid}/progress` is the same list (SP4 enriches it).

SP2 hooks: `@OnEvent(INVITATION_ACCEPTED)` → enrollments for `invitation.courseIds` (ids that no longer name a non-deleted course of the workspace are skipped and logged; `source = 'INVITATION'`, `assignedByUserId = invitedByUserId`); `@OnEvent(INVITE_LINK_JOINED)` → the same for `inviteLink.courseIds` (SP2 emits `MembershipActivatedEvent` only; SP3 adds `InviteLinkJoinedEvent(workspaceId, inviteLinkId, userId)` in `join.service.ts`, one line after the commit, plus its test). Both listeners run `withTenantTx(workspaceId)` and audit `enrollment.created { source }` per row.

### 4.6 Student access, locks and minimal progress (§8.5, §8.6)

`resolveLessonAccess(userId, lessonId)` / `resolveCourseAccess(userId, courseId)` (module `learn`): `crossTenantDb().enrollment.findFirst({ where: { studentUserId: userId, courseId } })` (D7) → no row or `REVOKED` → `403 ENROLLMENT_REVOKED` when a revoked row exists, else `404`; then `tenantDb(wid)`: membership of the caller `ACTIVE` (else `403 MEMBERSHIP_INACTIVE` / `403 GUARDIAN_CONSENT_REQUIRED` by status, reusing SP2's mapping); course `deletedAt: null` and `status ∈ {PUBLISHED, ARCHIVED}` (else `403 COURSE_NOT_AVAILABLE` — AC-CRS-02); teachers and admins never use these routes (they preview through the workspace routes).

Locks (`LockService.evaluate(wid, course, studentUserId)`): module `i` is locked when `unlockRule.type = 'PREVIOUS_MODULE_COMPLETED'` and the nearest previous non-optional module is below 100 % (`reason: 'PREVIOUS_MODULE_INCOMPLETE'`, `previousModule: { id, title, percent }` — AC-ENR-03); a lesson is locked when `course.sequentialLessons` and a required lesson before it in the same module is not `COMPLETED` (`reason: 'PREVIOUS_LESSON_INCOMPLETE'`, `previousLesson: { id, title }`). Locked content is still listed (title, lock, reason) but `GET /me/lessons/{lid}` → `403 MODULE_LOCKED` / `403 LESSON_LOCKED` with those `details`.

Progress (D-P8, the SP3 subset): `POST /me/lessons/{lid}/opened` → `LessonProgress` upsert `IN_PROGRESS`, `openedAt`; `POST …/complete` → `COMPLETED` (`completedManually = true`; `PDF` not yet opened → `409 LESSON_NOT_OPENED`); `POST …/uncomplete` → `IN_PROGRESS`. Each change recomputes `Enrollment.progressPercent = floor(100 × completed required lessons of non-optional modules / required lessons of non-optional modules)` (0 when the denominator is 0) and `completedAt` (set at 100 %, kept afterwards) inside the same `withTenantTx`, and sets `lastActivityAt`. SP4 replaces nothing here; it adds `progress` (segments), the automatic ≥ 90 % completion, the structure-change recompute job and the activity events.

`GET /me/courses` (every workspace, `PUBLISHED | ARCHIVED`, `ACTIVE` enrollment, ACTIVE membership) → `{ items: [{ course: { id, title, coverUrl, level, language, estimatedMinutes, status, workspace: { id, name }, teacher: { firstName, lastName } }, progressPercent, completedAt, lastActivityAt }] }`; `GET /me/courses/{cid}` → the structure with `locked`, `lockReason`, per-module `percent`, per-lesson `progress.status`, `media.status` (`PROCESSING` lessons shown « en cours de traitement », not openable → `409 MEDIA_NOT_READY`); `GET /me/lessons/{lid}` → `{ lesson, content | media, playback, images, progress, next: { id } | null }`.

## 5. Rich text (TEXT lessons, course description)

ProseMirror JSON (Tiptap) validated server-side by `RichTextDocSchema` (`@nibras/contracts`, zod, recursive, depth ≤ 20, serialised size ≤ 200 kB): nodes `doc`, `paragraph`, `heading` (`level` 1–3), `bulletList`, `orderedList`, `listItem`, `blockquote`, `codeBlock`, `hardBreak`, `horizontalRule`, `text`, `image` (`attrs: { mediaId: uuid, alt?: string ≤ 200 }` — never a URL); marks `bold`, `italic`, `underline`, `strike`, `code`, `link` (`href` `https?:` only, ≤ 2048, `rel`/`target` set by the renderer). Unknown node, mark or attribute → `422 VALIDATION_FAILED` with the path. The web renders the JSON with a React renderer (`RichText`, no HTML string, no `dangerouslySetInnerHTML`); the teacher edits with Tiptap (`@tiptap/react` + `starter-kit` + `extension-link` + a custom `mediaImage` node), loaded with `next/dynamic` on the editor route only. The course `description` uses the same schema without `image`.

```ts
  head(key): Promise<{ sizeBytes, contentType } | null>;
  getRange(key, start, end): Promise<Uint8Array>;
  signGetUrl(key, ttlS, { disposition: 'inline' | 'attachment', filename?, contentType? }): Promise<string>;
  delete(key): Promise<void>;
}
interface VideoProvider {
  readonly name: 'S3' | 'CLOUDFLARE_STREAM';
  readonly acceptedMimeTypes: readonly string[];
  createDirectUpload(input: { mediaId, filename, mimeType, sizeBytes, maxBytes, maxDurationS, ttlS }): Promise<
    | { mode: 'TUS'; uploadUrl; providerAssetId; expiresAt }
    | { mode: 'S3_MULTIPART'; storageKey; uploadId; expiresAt }>;
  getAsset(ref: { providerAssetId? , storageKey? }): Promise<{ status: 'PROCESSING' | 'READY' | 'FAILED'; durationS?, width?, height?, thumbnailUrl?, sizeBytes?, failureReason? }>;
  signPlayback(ref, { ttlS }): Promise<{ kind: 'HLS' | 'MP4'; url; expiresAt }>;
  delete(ref): Promise<void>;
  verifyWebhook(req: { rawBody: Buffer; headers: Record<string, string | undefined>; now?: Date }): { ok: true; events: VideoWebhookEvent[]; eventId: string } | { ok: false; reason };
}
```

- `S3StorageProvider` (`@aws-sdk/client-s3` + `s3-request-presigner`, `forcePathStyle` for MinIO, a second client on `S3_PUBLIC_ENDPOINT` for presigning when set). Keys: `w/{wid}/{kind}/{mediaId}/{sanitised filename}` (ASCII, ≤ 120 chars). `InMemoryStorageProvider` for unit tests of the services; the API/worker e2e suites use the real MinIO (D10).
- `S3VideoProvider` (**default**, `VIDEO_PROVIDER=s3`): passthrough — `createDirectUpload` opens a multipart upload through the storage provider; `getAsset` probes the stored MP4 (`probeMp4`: walks top-level boxes with ranged reads, `moov/mvhd` → duration, first video `trak/tkhd` → width/height; `moov` at the end of the file is found by following box sizes; WebM → duration `null`, dimensions `null`) ; `signPlayback` → presigned GET 2 h (`kind: 'MP4'`); `delete` → storage delete; `verifyWebhook` → `{ ok: false, reason: 'NO_WEBHOOKS' }`. Browser playback = progressive MP4/WebM in `<video>`; no transcoding, no HLS, no thumbnail — explicitly a dev/CI/staging and small-deployment provider (R5: every byte stays in the owner's bucket).
- `CloudflareStreamProvider` (`VIDEO_PROVIDER=cloudflare_stream`, D-P1): `createDirectUpload` → `POST /accounts/{id}/stream?direct_user=true` with `Tus-Resumable`/`Upload-Length`/`Upload-Metadata` (`maxDurationSeconds`, `requiresignedurls`, `expiry` = 1 h, `name`) → the `Location` header is the tus `uploadUrl`, `stream-media-id` the `providerAssetId`; `getAsset` → `GET /stream/{uid}` (`readyToStream`, `duration`, `input.width/height`, `thumbnail`, `size`, `status.errorReasonCode`); `signPlayback` → RS256 JWT (`jose`, `kid` = signing key id, `sub` = uid, `exp` = now + 2 h, `accessRules` none) → `https://{customerSubdomain}/{token}/manifest/video.m3u8` (`kind: 'HLS'`; `thumbnailUrl` = `…/{token}/thumbnails/thumbnail.jpg`); `delete` → `DELETE /stream/{uid}`; `verifyWebhook` → `Webhook-Signature: time=…,sig1=…`, HMAC-SHA256 over `${time}.${rawBody}` with the webhook secret, constant-time compare, `|now − time| ≤ 300 s`, `eventId = sha256(rawBody)` (D11), events `{ providerAssetId: uid, state: readyToStream ? 'READY' : status.state === 'error' ? 'FAILED' : 'PROCESSING', … }`. Unit-tested with `fetch` stubs and fixed vectors; never called in CI.
- `FakeVideoProvider` (tests): scripted `getAsset` answers and a `signPlayback` that returns `https://video.test/{id}?exp=…`.

## 9. Security & privacy

- **Tenant isolation.** Six 🏢 tables under RLS + `tenantDb`; `/me` learn routes resolve the tenant through a `studentUserId`-filtered cross-tenant read then switch to `tenantDb(wid)` (D7); the isolation suite (SP1.6 T6) gets `FOREIGN_PARAMS` fixtures for `:cid`, `:mid`, `:lid`, `:mediaId`, `:uid` (enrollments) and `FOREIGN_BODIES` for `mediaAssetId`, `coverMediaId`, `content` image `mediaId`, `studentUserIds`, `moduleIds`, `lessonIds`, `ownerUserId`; every write route is in a table or in `BODYLESS_WRITE_ROUTES` (`publish`, `unpublish`, `archive`, `restore`, `opened`…).
- **No raw storage URL** leaves the API (every URL is presigned and short); no bucket is public; keys are not listable; `Referrer-Policy: no-referrer` already set.
- **Bearer tokens** (D-O8) with a 30/h/user window; residual risk accepted by the owner; the watermark carries the viewer's email.
- **Uploads** are presigned per part (1 h) and bound to one object key; `complete` verifies size, signature and quota before anything becomes readable; a failed check deletes the object.
- **Webhooks**: HMAC verified on the raw body, ± 5 min, stored before processing, processed by a job, idempotent by event id and by state machine.
- **Rich text**: whitelist schema, no HTML, links `https?:` only with `rel="noopener noreferrer"`.
- **Secrets**: `S3_SECRET_KEY`, `CLOUDFLARE_*` are API/worker only; the web gets `MEDIA_ORIGINS` (origins, not secrets); `assertDeployableEnv` refuses `minioadmin` and any `PLACEHOLDER_SECRETS` value for the new keys outside development; `compose.staging.yml` allocates `S3_*`, `VIDEO_PROVIDER`, `CLOUDFLARE_*` to `api` and `worker` only (the SP1.6 compose test is updated).
- **Audit**: every mutation above; playback issuance is logged and metered, not audited (D13).
- **Minors**: no third-party analytics; Cloudflare receives the video bytes and a signed token, never a user identity (the JWT has no user claim — bearer by design).
