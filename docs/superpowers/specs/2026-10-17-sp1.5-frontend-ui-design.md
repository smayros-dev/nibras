# SP1.5 — Frontend & GUI design (tokens, component library, app shell, hardening)

**Date:** 2026-10-17
**Status:** Implemented (branch `ui/redesign`, T0–T17) — plan: `docs/superpowers/plans/2026-10-17-sp1.5-frontend-ui.md`; deviations in §12; runbook: `docs/runbooks/frontend.md`
**Scope:** `apps/web`, `packages/ui`, `packages/i18n`, `packages/config` (lint/tailwind), one additive change in `apps/api` (zod issue codes). No schema, no new endpoints.
**Authoritative spec:** `PRD.md` v2.1 — §1.4 (réseau instable, PWA), §8.16.1 (i18n/RTL), §9 (navigation), §9.5 (états des écrans), §14.1 (budget performance), §14.5 (WCAG 2.1 AA, RTL, cibles ≥ 44 px), §14.6 (PWA installable, shell hors-ligne), §14.7 (HSTS, CSP stricte avec nonce, frame-ancestors), §20 Q1 (pas de marque : variables centralisées), §22 (choix UI laissés au builder : « Tailwind + Radix/shadcn ou autre »).

## 1. Why this sub-project

SP1 shipped working auth, settings, workspace and admin screens with a three-component UI kit (`Button`, `Form`, `AppShell`). A frontend audit found 15 defects (listed in §9, all verified in code) and no visual system: grey Tailwind defaults, physical colours hard-coded in pages, no dark theme, a header nav that links to five 404 routes, no logout, and sessions that die after the 15-minute access token because nobody calls `POST /auth/refresh`. SP2–SP11 will add many screens; building them on today's base multiplies every defect. SP1.5 lays the design system and fixes the audit before the next feature plan starts.

## 2. Visual direction — "calm, trustworthy, school-grade"

The user is a teacher on a phone between two lessons, a parent reading a consent email, a 15-year-old on a mid-range Android on 4G. The interface should feel like a well-kept notebook, not a dashboard SaaS: generous whitespace, one accent colour, no gradients, no decorative illustration, system-quality motion.

- **Palette.** One brand hue, a deep **lagoon teal** (primary 600 `#0f766e`), used for primary actions, links and the active nav item only. A warm **amber** accent (`#b45309`) is reserved for warnings and the onboarding checklist; **red** (`#b91c1c`) for destructive actions and the future "live" indicator. Neutrals are warm greys (stone-like) so large white surfaces do not glare on phones. Every colour has a light and a dark value; components reference semantic tokens, never the raw scale.
- **Typography.** One family for the three scripts: **IBM Plex Sans Arabic** (already self-hosted through `next/font`, covers Latin and Arabic; PRD §8.16.1). Western digits in Arabic (D-P16) are left to `Intl` — no `font-variant-numeric` tricks. Scale (px/line-height): 12/16 caption · 14/20 body-sm · 16/24 body (default, never smaller on mobile inputs to avoid iOS zoom) · 18/28 lead · 20/28 h3 · 24/32 h2 · 30/36 h1 · 36/40 display (landing only). Weights 400/600/700.
- **Shape.** Radius `sm` 6 px (inputs, badges), `md` 10 px (buttons, cards), `lg` 14 px (dialogs, sheets), `full` (avatars, switch). Borders 1 px semantic `border`; shadows only on floating surfaces (menus, dialogs, toasts): `shadow-sm` for cards in dark mode is replaced by a 1 px border.
- **Density.** 4 px base grid; touch targets ≥ 44 px (PRD §14.5) — every button, nav item, row action and switch has `min-height: 44px` on pointer:coarse and 36 px on fine pointers.
- **Motion.** 150 ms (hover/press), 200 ms (menus, sheets, toasts), `ease-out`; everything under `@media (prefers-reduced-motion: reduce)` collapses to 0 ms. No motion on page load.
- **Direction.** Layout is written with logical properties only (`ps-*`, `me-*`, `start-0`, `text-start`, `rounded-s-*`). Direction comes from `<html dir>`; Radix gets it through `DirectionProvider`. Directional icons (chevrons, arrows, "back") flip with a single `rtl:-scale-x-100` utility; non-directional ones (search, settings) do not. The Tailwind `rtl:` variant is allowed **only** for that icon flip.
- **Themes.** `light` (default), `dark`, `system`. The theme is stored per browser (`localStorage` `tt-theme`) and applied as `data-theme="light|dark"` on `<html>` before first paint by `next-themes` (nonce-carried inline script). The semantic tokens switch; components carry no `dark:` classes except for shadows → borders.

## 3. Design tokens (`packages/ui/src/tokens.css`)

Single source of truth, CSS-first (Tailwind v4 `@theme`); the SP0 JS preset (`packages/config/tailwind/preset.ts`) is deleted. Three layers:

1. **Brand (swappable, PRD Q1).** `--brand-name`, `--brand-hue` scale `--color-brand-50…950`, `--color-accent-*`, `--font-sans`, `--radius-*`. Also exported as TypeScript `BRAND` in `packages/ui/src/brand.ts` (`name: 'Plateforme cours'`, `shortName`, `themeColor`, `backgroundColor`) for the manifest, emails later, and `<meta name="theme-color">`. Replacing the brand = editing one CSS block and one TS object.
2. **Semantic (what components use).** Defined on `:root` (light) and `:root[data-theme="dark"]` (dark): `--color-bg`, `--color-bg-subtle`, `--color-surface`, `--color-surface-raised`, `--color-fg`, `--color-fg-muted`, `--color-fg-subtle`, `--color-border`, `--color-border-strong`, `--color-primary`, `--color-primary-hover`, `--color-primary-fg`, `--color-primary-subtle`, `--color-danger{,-hover,-fg,-subtle}`, `--color-warning{,-fg,-subtle}`, `--color-success{,-fg,-subtle}`, `--color-info{,-fg,-subtle}`, `--color-focus`, `--color-overlay`. Exposed to Tailwind through `@theme inline` so classes read `bg-surface`, `text-fg-muted`, `border-border`, `bg-primary`, `text-primary-fg`.
3. **Scales.** `--text-*` + `--leading-*` (the type scale above), `--radius-sm/md/lg/full`, `--shadow-sm/md/lg`, `--duration-fast/base`, `--ease-out`, `--size-touch: 44px`.

Contrast is enforced by a unit test: every `fg`/`bg` semantic pair declared in the token file passes WCAG AA (≥ 4.5:1 text, ≥ 3:1 for `fg-subtle` on `bg` and for `border-strong` on `surface`) in **both** themes. Light reference values: `bg #faf9f7`, `surface #ffffff`, `fg #1c1917`, `fg-muted #57534e`, `border #e7e5e4`, `primary #0f766e`, `primary-hover #115e59`, `primary-fg #ffffff`, `focus #0d9488`. Dark reference values: `bg #0c1116`, `surface #141b22`, `surface-raised #1b242d`, `fg #f1f5f9`, `fg-muted #a8b0ba`, `border #263039`, `primary #2dd4bf`, `primary-hover #5eead4`, `primary-fg #042f2e`. The implementer may tune any value as long as the contrast test and the e2e visual checks stay green.

## 6. Session resilience (audit #1, #10)

- **Client calls.** `api` (openapi-fetch) gets a `fetch` wrapper: on `401` from any route except `/auth/login`, `/auth/refresh`, `/auth/logout`, `/auth/2fa/*`, it awaits a **single in-flight** `POST /api/v1/auth/refresh` (promise shared by all concurrent callers), then retries the original request **once**; a second `401`, or a refresh failure, resolves to the original `401` and dispatches a `tt:session-expired` event that the shell turns into a redirect to `/login?next=<current path>`. Request bodies are replayed from the stored `init` (JSON only; no streams exist today).
- **Proactive refresh.** `<AuthRefresher>` (client, in the `(app)` layout) schedules a refresh at 13 min after mount and after every successful refresh, and on `visibilitychange` → visible when the last refresh is older than 13 min; so RSC navigations rarely hit an expired cookie. (Access TTL is 15 min; the 2 min margin covers clock drift and slow networks.)
- **Server navigation.** The `tt_refresh` cookie is scoped to `/api/v1/auth`, so neither `proxy.ts` nor a server component can see or forward it; refresh must be initiated by the browser. When the `(app)` layout's `GET /me` returns `401` it redirects to `/[locale]/auth/resume?next=<path>`, a tiny client page that POSTs `/api/v1/auth/refresh` (cookies set by the API flow back same-origin through the rewrite) and then `router.replace(next)`; on failure it goes to `/login?next=`. Loop guard: the resume page sets a cookie `tt_resume=1; Max-Age=20; Path=/` before redirecting back; the layout sends a `401` **with that cookie present** straight to login. (No backend change: a marker cookie set by the API would save one round-trip for anonymous visitors and is noted as a follow-up.)
- **Logout.** User menu → `POST /api/v1/auth/logout` (public, clears both cookies) → `router.replace('/login')` and `router.refresh()`.
- **`next` deep link.** `sanitizeNext` accepts only `^/[^/\\]` paths (rejects `//`, backslashes, schemes, and anything with `\r\n`); the login form carries `next` into the 2FA page through `sessionStorage` `{ challengeToken, remember, next }` and the 2FA verify/recovery calls send the real `remember`.

## 8. Accessibility & RTL acceptance (this sub-project's DoD)

- `axe-core` (Playwright) reports no `serious`/`critical` violations on: landing, login, register, dashboard, settings/profile, workspace members, audit log, admin workspaces — in **fr and ar**, desktop and Pixel 7.
- Keyboard: every dialog traps and restores focus; menus open with Enter/Space/ArrowDown; `Escape` closes; the skip link is the first tab stop; bottom nav items are links.
- Every repeated row action has a unique accessible name (`aria-label="Changer le rôle — Sana K."`).
- No raw message keys (`RAW_KEY` regex) on any visited page, in text or `aria-label`/`title`.
- `dir="rtl"` on `<html>` in ar; `getComputedStyle(body).direction === 'rtl'`; sidebar sits at inline-start (so on the right in ar) — asserted by bounding boxes in e2e.
- Lint: zero physical left/right utilities in `apps/web` and `packages/ui`.
- Zoom 200 % and 360 px width: no horizontal scroll on the same pages.

## 12. Implementation notes and deviations

Recorded at the close of SP1.5 (T17); the commit bodies carry the details.

- **Brand.** The product is named **Nibras** (نبراس; owner decision, §20 Q1), so `BRAND.name` is
  `Nibras`, not the `Plateforme cours` placeholder of §3.
- **First-load budget.** Measured with `apps/web/scripts/first-load-js.mjs` (Next 16 no longer
  prints First Load JS): `/[locale]/app` 226.4 kB gzip, largest route 233.8 kB, all < 250 kB.
  Reaching it needed a zod-free `@tt/contracts/web` entry (constants, `createApiClient`): web
  code that imported one value from `@tt/contracts` shipped every zod schema (≈ 300 kB per
  route). An ESLint rule keeps browser code on the web entry; CI runs the budget after the build.
- **i18n.** No `confirm.*` namespace (dialogs use `settings.*` keys and `common.cancel`); consent
  type labels live under `settings.consents.types`. The T17 unused-key guard removed 25 SP0/SP1
  leftovers (`nav.courses|students|sessions|messages|notifications`, `health.ok`, unused
  `settings.*`, `workspace.*`, `members.*` and `admin.*` keys); the consent gate's new-tab links
  carry an sr-only `common.newTab` cue (the register form's terms links do not: inside the
  checkbox label the cue would repeat in its accessible name).
- **Components.** `Tabs` also exports `TabsRoot/List/Trigger/Content` (a server component cannot
  dot into a client export); table padding lives in `.tt-table` (stacked mobile layout);
  Checkbox/Switch descriptions sit outside the label; `Textarea` auto-resizes with
  `field-sizing: content`; `ShellLabels` has no `openMenu`.
- **Shell.** `buildNavModel` takes `locale` (hrefs are locale-prefixed); the workspace switcher and
  user-menu links use full navigations (the nav model is built from `x-pathname`); the switcher
  shows from one workspace; the theme toggle renders without a value until mounted.
- **Session.** 401s with credential codes (`INVALID_CREDENTIALS`, `TWO_FACTOR_INVALID`) are not
  refreshed; `SESSION_REVOKED` ends the session without a retry; the proactive refresher checks
  every 60 s and keeps the session while offline.
- **Consent gate.** Keyed on the pending types and versions; the accept button stays busy only
  for the refresh transition, so a gate still pending after the refresh (deploy skew) is usable.
- **Headers.** The proxy matcher keeps prefetch requests (the `(app)` layout needs `x-pathname`
  during prefetch); `global-error.tsx` has no inline script and is untouched.
- **Lint.** Test sources are exempt from the logical-CSS rule (test titles are prose); the tenancy
  bans still apply there.
