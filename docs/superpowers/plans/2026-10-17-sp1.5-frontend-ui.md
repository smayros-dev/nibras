## Review Focus

Five failure modes the spec implies but no e2e scenario of SP1 exercises; each has its test in the owning task.

1. **Refresh storms and lost bodies** — ten concurrent client calls that all `401` must trigger exactly one `POST /auth/refresh` and each be retried once with its original JSON body; a `401` on `/auth/refresh` itself must never retry. → T6.
2. **Theme and direction before first paint** — in `ar` with the dark theme stored, the first HTML response carries `dir="rtl"` and the inline theme script has the request nonce; no flash, no CSP violation in the console. → T8, T15.
3. **Role gating is server-truth, not UI-only** — a `TEACHER` must not see role/remove actions, and if they call the API anyway the `403` renders a translated toast (no crash). → T11.
4. **Out-of-order filter responses** — typing `a`, `ab` quickly must show `ab`'s result even if `a`'s response arrives last (AbortController + sequence guard). → T11, T12.
5. **Offline navigation returns the localised offline page** — with the SW installed (CI, production build), `context.setOffline(true)` then navigating to `/ar/app` shows `/ar/offline` content in RTL. → T14, T16.
